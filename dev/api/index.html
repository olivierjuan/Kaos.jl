Graphs

Kaos.BasicDirectedGraph — Type
BasicDirectedGraph()

Directed graph with contiguous 1-based node and arc identifiers, port of rcspp::BasicDirectedGraph.

Build with add_node! / add_arc!, then freeze the adjacency with close!. Nodes and arcs are numbered in creation order; arcs are kept in ascending identifier order inside each adjacency list.

The adjacency is stored in CSR form (out_start/out_arc/out_node and in_start/in_arc/in_node, 0-based offsets into 1-based position arrays), which keeps the solver hot loop allocation-free.

Kaos.AbstractRCSProblem — Type
AbstractRCSProblem

Supertype for resource-constrained shortest path problems. A concrete problem only needs to implement the required interface below; everything else has a default.

Required methods:

methodC++ counterpart

dest_node(p)get_dest_node
initial_resource(p)get_initial_resource
arc_resource(p, a)per-arc resource consumed by extend

methoddefaultC++ counterpart

Kaos.dominates — Function
dominates(a, b) -> Bool

Strict Pareto dominance of resource a over b, exactly as specified in the library documentation (docs/main.dox, DOMINANCE): a dominates b iff a[i] <= b[i] for every component and a[i] < b[i] for at least one. Consequently Pareto-equivalent labels (equal resources) are not dominated and all of them stay extensible, as the NodeSolver/PathSolver specifications require.

The compares are statically unrolled by StaticArrays (all(a .<= b) && any(a .< b)), keeping the hot path branch-light and allocation-free. Custom resource types must implement dominates(a, b); problems may override the problem-level dominates(problem, a, b) (the C++ TestProblem uses the weaker a <= b componentwise relation, reproduced by its Julia port for parity).

source

Filters

Kaos.AbstractPathFilter — Type
AbstractPathFilter

Supertype of label filters, port of the C++ PATH_FILTER template parameter. A filter implements:

  • is_candidate(filter, problem, resource, node, incumbent) — accept/reject a feasible extension (port of isCandidate);
  • path_priority(filter, problem, resource, node) — heap priority for the path solver (port of getPathPriority);
  • node_priority(filter, problem, node) — node priority for the node solver, delegated to node_priority(problem, node) by both shipped filters.
source
Kaos.BasicFilter — Type
BasicFilter()

Accepts every feasible extension, port of rcspp::PathFilter. Path priority delegates to path_priority(problem, r, n).

source
Kaos.BoundedFilter — Type
BoundedFilter(p::AbstractRCSProblem)

A*-style filter, port of rcspp::BoundedPathFilter. Precomputes, for every node, a lower bound node_bounds[n] on the cost of reaching the destination (backward DP over the topological order, so p must be a DAG), then rejects extensions whose resource_cost + node_bounds[node] already reaches the incumbent. Path priority is -(cost to go).

source

Lower bound of the total cost of any completion of resource r at node n.

Solvers

Kaos.NodeSolver — Type
NodeSolver

Node-keyed label-setting solver, port of rcspp::NodeSolver. Nodes carry a priority heap; popping a node extends every still-extensible efficient label parked on it (one-shot consuming iteration of its ExtensibleFront).

Run with solve: solve(problem, NodeSolver, BasicFilter).

source
Kaos.PathSolver — Type
PathSolver

Path-keyed label-setting solver, port of rcspp::PathSolver. Extensible labels live in a priority heap (best-first for BoundedFilter); popped labels are extended arc by arc, destination labels only update the incumbent.

Run with solve: solve(problem, PathSolver, BoundedFilter).

source

Run a label-setting search for the resource-constrained shortest path of problem, port of rcspp::NodeSolver::solve / rcspp::PathSolver::solve. The graph must be close!d. Kaos.path_argmin — Function

Node path of the terminal label (no children) minimising predicate, port of Paths::path_argmin. predicate(best_node, best_resource, candidate_node, candidate_resource) returns true when the candidate replaces the current best; ties keep the earliest-created label, mirroring the C++ scan order. Kaos.PathTable — Type
PathTable{R,C}

Structure-of-arrays table of every label (partial path) explored by a solver, port of rcspp::Paths. Row i encodes: label i ends at node[i], was obtained by extending label parent[i] over arc[i], and carries resource[i]. Row 1 is the root (source, empty path).

Cost type C is that of resource_cost(resource[1]).

Fronts and heap (internal, documented for completeness)

Kaos.ExtensibleFront — Type
ExtensibleFront{R}()

Per-node Pareto front of efficient labels that still deserve extension; port of rcspp::ParetoFrontValid. Iteration is consuming: an entry is yielded at most once, exactly when it is still flagged extensible.

Intentional fix over the C++ original: its begin() did not skip a consumed first entry, so re-popping a node re-extended an already-extended label — wasted work that weak dominance filtered afterwards anyway.

source
Kaos.EfficientFront — Type
EfficientFront{R}()

Per-node Pareto front of efficient labels; port of rcspp::ParetoFrontNew (used by the path solver, which never iterates it — only dominance queries).

Kaos.PriorityHeap — Type
PriorityHeap{K,P}()

Binary heap of keys with priorities, port of rcspp::Heap. init! seeds it, push!(h, key, priority) inserts, and pop!(h) removes and returns the key with the largest priority (callers pass negated priorities to get min-first behaviour, exactly like the C++ code built on std::make_heap).
